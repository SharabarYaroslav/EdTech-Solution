01Фундаментальна різниця: Styles проти Variables

Централізоване управління візуальними атрибутами у Figma базується на синергії двох механізмів: Styles (Стилів) та Variables (Змінних):

  • Styles призначені для збереження складених багатокомпонентних пресетів — наприклад, комплексної типографіки (шрифт + кегль + інтерліньяж), багатошарових градієнтів, комбінацій тіней або модульних сіток. Стилі не підтримують посилання один на одного.
  • Variables зберігають єдині атомарні значення конкретних типів і виступають прямим аналогом CSS Custom Properties (--var) та Design Tokens у коді. Вони підтримують багаторежимність (Modes) для миттєвого перемикання тем (Light / Dark), локалізацій (UA / EN) або щільності інтерфейсу (Mobile / Desktop), а також механізм Aliasing (вкладене посилання однієї змінної на іншу).

02Типологія Variables та порівняльна матриця

Сучасна специфікація Figma охоплює шість спеціалізованих типів Variables:

🎨

Color & Number

Кольори та числа →
Візуальні та просторові атомиColor керує суцільними заливками та обводками; Number задає падінги, інтервали Gap, радіуси скруглення, ширину/висоту та кегль тексту.
🔤

String & Boolean

Рядки та логіка →
Контент, локалізація та станиString підставляє текстові рядки (мови UA/EN) або назви гарнітур; Boolean перемикає видимість шарів та варіанти між режимами.
⏱️

Timing & Easing

Кінетика анімацій →
Токени руху (Motion Tokens)Timing зберігає тривалість переходів у мілісекундах (напр., 200ms), а Easing — математичні криві прискорення та фізичні пружини.
Критерій порівнянняStyles (Стилі)Variables (Змінні)
Структура даних Складені властивості (градієнти, комбінації тіней, весь набір параметрів тексту). Одне атомарне значення конкретного типу (HEX-код, число у px, рядок, булевий стан).
Підтримка режимів (Modes) Відсутня (статичний пресет). Повна підтримка (Light/Dark, Mobile/Desktop, мовні локалі).
Aliasing (Токенізація) Неможливо послатися стилем на інший стиль. Підтримує глибоку ієрархію посилань (змінна посилається на змінну).
Синхронізація з кодом Генерує класи або набори CSS-правил. Пряма конвертація у JSON Design Tokens та CSS Variables (--token).

03Трьохрівнева архітектура токенізації (Design Tokens)

Професійні дизайн-системи організовують змінні у три логічні рівні за допомогою механізму Aliasing:

  1. Primitive Tokens (Базові / Примітиви) — визначають сирі константи палітри та масштабу без контексту використання (наприклад, blue-500 = #0C8CE9, space-8 = 8px).
  2. Semantic Tokens (Семантичні) — описують функціональне призначення у продукті, посилаючись на примітиви (наприклад, color-bg-brand посилається на blue-500).
  3. Component Tokens (Компонентні) — вузькоспеціалізовані змінні, які закріплюють семантичні параметри за конкретними вузлами інтерфейсу (наприклад, button-primary-bg → color-bg-brand).
🚀 Масштабованість та миттєвий ребрендинг

Під час ребрендингу достатньо змінити значення кольору лише в одному місці — у Primitive Tokens. Усі семантичні зв'язки, компоненти на сотнях екранів та підключені репозиторії коду оновляться автоматично за частки секунди.
