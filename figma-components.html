01Архітектура перевикористання: Main Component vs Instances

Компонентна модель Figma реалізує фундаментальний принцип програмування DRY (Don't Repeat Yourself), забезпечуючи масштабованість інтерфейсів. Система ділиться на два ієрархічні рівні:

  • Main Component (Головний компонент) — маркується фіолетовою іконкою з чотирма заповненими ромбами (❖). Виступає первинним джерелом правди (Single Source of Truth): будь-яка структурна зміна у ньому миттєво транслюється на всі підпорядковані копії у проекті або пов'язаних бібліотеках.
  • Instance (Екземпляр) — маркується порожнистим ромбом (◇). Це залежна копія, яка використовується безпосередньо в макетах. Екземпляри підтримують локальні перевизначення (Overrides) — зміну тексту, кольорів заливки, приховування шарів або заміну іконок — без розриву зв'язку з материнським компонентом.

02Component Sets (Варіанти) та 5 типів Component Properties

Для групування споріднених станів одного елемента (наприклад, кнопка у станах Default, Hover, Pressed, Disabled та розмірах S, M, L) використовується контейнер Component Set (Варіанти), окреслений фіолетовою пунктирною рамкою.

Щоб уникнути комбінаторного вибуху (створення сотень майже однакових варіантів), сучасна архітектура Figma розділяє налаштування на п'ять спеціалізованих типів Component Properties:

Тип властивостіІнженерна механіка та застосування в дизайн-системі
Variant Property Керує фундаментальними розмірами, типами та візуальними модифікаціями (State = Default / Hover / Disabled, Size = S / M / L).
Boolean Property Логічний перемикач true / false, що керує видимістю конкретного шару (наприклад, ShowIcon = true, HasBadge = false, IsLoading = false).
Instance Swap Дозволяє миттєво замінити вкладений підкомпонент через інспектор, обираючи його із попередньо заданого списку Preferred Icons.
Text Property Виносить редагування текстового рядка прямо на панель інспектора, усуваючи потребу подвійного кліку вглиб структури шарів.
Slot Property Створює всередині компонента виділену вільну зону (слот) для безпечного розміщення довільного стороннього контенту (наприклад, у модальному вікні чи картці).

04Еволюція системи (2026) та Interactive Components

З березня 2026 року Figma офіційно скасовує застарілий режим «спрощених екземплярів» (Simplified Instances). Тепер усі властивості та шари відображаються у панелі Properties за замовчуванням, що робить структуру компонента повністю прозорою для дизайнерів та фронтенд-розробників.

Функціонал Interactive Components дозволяє зв'язувати варіанти всередині самого Component Set прототипними переходами Change to. Наприклад, налаштувавши перехід While hovering → Change to Hover один раз у материнському наборі, кожна копія кнопки або чекбокса у всьому проекті автоматично стає інтерактивною під час запуску режиму презентації.

🧮 Оптимізація розміру дизайн-системи: $24 \to 12$

Якщо кнопка має 2 типи (Primary / Secondary), 3 розміри (S / M / L) та 4 стани (Default / Hover / Pressed / Disabled), це створює $2 \times 3 \times 4 = 24$ варіанти. Замість того, щоб дублювати їх для версій «з іконкою» та «без іконки» (отримуючи 48 варіантів!), призначте іконці Boolean Property — це скорочує матрицю варіантів рівно вдвічі при збереженні повної гнучкості.
