01П'ятирівнева організаційна ієрархія простору

Систематизація робочих файлів у Figma визначає швидкість адаптації нових спеціалістів у команді та прозорість процесу передачі макетів у розробку (Handoff). Ієрархія Figma вибудовується за строгою 5-рівневою схемою:

Workspace (корпоративний рівень) → Team (продуктова команда) → Project (напрям або модуль) → File (робочий файл макета) → Page (сторінка файлу).

Правильний розподіл файлів за проектами усуває хаос у каталозі та полегшує гнучке налаштування прав доступу (Can view / Can edit) для дизайнерів, менеджерів, замовників і розробників.

02Архітектура сторінок усередині продуктового файлу

Стандарт продуктового дизайну вимагає чіткої структури сторінок усередині кожного файлу. Перша сторінка обов'язково відводиться під обкладинку (Cover Page) — стандартизований фрейм розміром 1920×960 px, що містить назву проекту, статус готовності, версію та контакти лід-дизайнера.

Наступні сторінки чітко розмежовують користувацькі шляхи (User Flows), бібліотеку локальних компонентів (Design System), фінальні екрани десктопних і мобільних версій, а також архів застарілих ітерацій.

Типова сторінка файлуВміст та робоче призначення
Cover (Обкладинка) Фрейм 1920×960 px з бейджем статусу (In Progress, Review, Approved), авторами та посиланням на документацію.
Flow / Architecture Діаграми інформаційної архітектури, User Flows та вайрфрейми користувацьких сценаріїв.
Design System / UI Kit Локальні компоненти, варіанти, колірні та типографічні токени, специфічні для даного файлу.
Desktop Screens Зафіксовані екрани для комп'ютерів, згруповані у Секції за сценаріями використання.
Mobile Screens Адаптивні мобільні екрани (iOS / Android) з урахуванням системних гайдлайнів.
Archive Проміжні концепти, відхилені варіанти та застарілі макети для збереження історії пошуку рішень.
🖼️ Інженерний етикет обкладинки

Клацніть правою кнопкою миші на фреймі 1920×960 px на першій сторінці та оберіть «Set as cover». Тепер у загальному каталозі команди цей файл матиме інформативне прев'ю зі статусом готовності макета.

03Слейш-синтаксис в іменуванні активів та тренажер

Для логічної ієрархії компонентів та стилів застосовується слейш-синтаксис із роздільником «/». Figma автоматично інтерпретує слеш як створення вкладеної папки в інспекторі активів (Assets) та меню швидкої заміни екземплярів (Instance Swap).

Приклад: назва компонента Icons/Navigation/Arrow-Left автоматично розмістить іконку в папку Navigation всередині категорії Icons.
